# 拼多多数据挖掘

Windows 本机辅助工具：按搜索词抓取商品，支持关键词、禁用词、价格和标签筛选，以及结果查看和词条分组。

## 运行

需要 Python 3.13、Microsoft Edge 或 Chrome，以及 WebView2 Runtime。

```powershell
python -m pip install -r requirements.txt
python app.py
```

在界面中导入自己的登录信息，再开始搜索。关键词匹配商品标题，多个关键词必须全部包含；留空不限。

## 代码结构

- `app.py`：桌面入口；`pdd_search.py`：命令行入口。
- `pdd/browser/`：浏览器会话和人工验证交互。
- `pdd/scraping/`：解析、筛选、翻页和采集。
- `pdd/storage/`：商品结果、筛选条件和词条分组保存。
- `pdd/services/`：登录和抓取任务管理。
- `pdd/server/`：本机接口。
- `web/js/core/`：通用工具；`web/js/features/`：功能模块；`web/js/app.js`：组装与刷新。
- `tests/`：功能回归；`build/`：原有打包脚本。

登录信息和抓取结果保存在 `cookie.txt`、`data/`，开源时不要上传。`.artifacts/`、`__pycache__/` 和构建缓存不属于源码。项目仍在开发，店名识别、数据更新等待办以 AGENTS.md 为准。

搜索接口返回 HTTP 429 或接口繁忙（40002）时，软件保留当前页面和已读商品，不用从第一页重来。短期限速会显示自动重试倒计时：没有服务器等待时间时，首次至少等 60 秒，连续失败时翻倍；服务器要求更长时间就等更久。未读到新商品前最多自动尝试 3 次。等待超过 5 分钟、恢复请求没有带来新商品，或只有网页繁忙提示时，桌面端改为暂停，等待下限结束后由你选择“继续抓取”或停止；命令行则保留结果并结束。登录失效（40001）需重新登录。

桌面界面的“累计商品目标”包括同词条历史数据中符合当前筛选条件的商品，按商品 ID 去重。例如已有 800 条、目标 1000，只需再新增 200 条；已经达标时不会再打开抓取页面。停止后重新开始会重新打开网站搜索页，累计数据仍保留，不代表可以跳过网站前面的分页。

为减少连续翻页触发限速，软件在最近 60 秒已观察到 6 次搜索请求时不再主动翻页，并等待在途请求和页面渲染。遇到限速后，本次会话后续翻页也会放慢。这是软件的保护策略，不是网站公布的配额，也不保证某个词条一定有 1000 条可访问的结果。

如果只读到首屏，软件会检查滑动前后列表位置；连续两次滑动没有移动时，改为滚动可见的列表容器，不跳页、不补造数据。任务诊断中的 `api_requests`、`api_responses` 和 `container_scrolls` 分别是观察到的搜索分页请求数、响应数和使用容器滚动的次数。

网站要求验证时，点击任务栏的“人机验证”，在软件内按网站提示点击或拖动。优先显示搜索页上的验证；若搜索响应给出明确的本站 HTTPS 验证地址，则在同一登录会话内打开它，保留原来的搜索页。不要粘贴验证码链接或请求头。单纯的 429 仍走冷却，不会提示做验证码。

复测时可用上次停在 180 条的词条，把“累计商品目标”设为 1200，保持软件打开。以“累计符合条件”和“本次新增”为准，不以响应次数算商品数。若仍未达标，结束任务后查看该词条的 `.run.json`：`last_limit_scanned` 是最近一次限速时本次已读的去重数量，`auto_recovery_attempts` 是自动重试次数，`rate_limit_recoveries` 是重试后读到新商品的次数，`stop_reason` 是结束原因。
